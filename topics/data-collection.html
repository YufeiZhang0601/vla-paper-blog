UMI 开源数据导航：我核实到目前能直接拿到什么

如果只谈论文，`UMI` 这条线已经很热；但如果只谈真正能下载、能复现、能训练的数据，情况其实比很多人想象得更复杂。更准确的做法，是把它们分成三类看：原版官方上游数据、规模化 UMI-style 数据、以及带新模态的新一代 handheld 扩展。

1. 原版 UMI 官方数据：example_demo_session

Stanford 官方原始示例会话，包含多段 GoPro MP4，最适合第一次跑通 `UMI` 的完整数据后处理链：视频、SLAM、位姿恢复，再到训练用 `Zarr`。如果你想理解什么叫“UMI 数据是被构造出来的”，而不是“直接拿视频喂模型”，这就是起点。

数据目录 / 代码 / 相关文章：UMI RSS 2024

2. 原版 UMI 官方训练集：cup_in_the_wild

这是最标准的官方训练数据入口。Stanford 数据目录里能直接看到 `cup_in_the_wild.zarr.zip`，大小约 16GB。它仍然是理解 `UMI` 典型 observation / action 组织方式最好的单任务基准，也最接近“传统 UMI”本体。

直接下载 / LeRobot 转换版 / 相关文章：UMI RSS 2024

3. UMI Robot Dataset Community

这不是一个单独数据集，而是当前最有用的社区索引和格式说明页。它把 `UMI-like` 数据共享原则、`Zarr` 结构、episode 组织方式和 replay buffer 读取方法都写得很清楚。对于任何想自己做 handheld / robot-free 数据的人，这个页面几乎就是最实用的参考模板。

社区索引 / 相关文章：UMI RSS 2024

4. FastUMI-Data

`FastUMI` 是目前最成熟的大规模 `UMI-style` 数据之一。论文和 Hugging Face 页面都指向：超过 1 万条真实演示、覆盖 22 个任务，总量约 2.37TB。它不是 Stanford 原版 UMI，但非常适合作为“UMI 思路放大后如何形成规模化数据生产线”的代表。

数据集 / 代码 / 相关文章：FastUMI

5. FastUMI-100K 与鹿明 FastUMI 全家桶

`FastUMI-100K` 更进一步，它不只是“更大的 FastUMI”，而是开始明显朝 foundation-model 量级推进。论文写的是 100K+ trajectories、54 个任务、约 600 小时交互数据；当前 Hugging Face 仓库已经公开，页面显示约 1.4TB。对关心“手持无本体数据能否真正做大”的人，这条线现在必须跟。

更值得关注的是：背后的鹿明机器人（深圳）已经在 AWE 2026 发布了整套商业化产品矩阵 FastUMI 全家桶——Pro（量产适配 90% 机械臂）、Ego（第一人称 3mm 定位）、Go（背包形态）、Touch（6 轴协作臂）。已交付 100 万条真实数据、覆盖 10 大场景 / 40+ 任务，并上线"FastUMI Pro 数据超市"。这是目前 UMI 路线走得最深的产业化尝试。

100K 数据集 / 论文：FastUMI-100K / FastUMI 官网 / 全家桶首发 / 腾讯新闻深度 / FastUMI 数据超市

6. exUMI

`exUMI` 是目前最值得一起看的 tactile 扩展。它把原版 UMI 的视觉接口升级成了 vision + tactile + 更稳 proprioception 的 portable system。上游 Hugging Face 仓库 `silicx/exUMI` 已公开，页面总量约 134GB，按任务提供 `zarr.zip` 和原始视频。它的重要性在于：这已经不是单纯“再多收一些 UMI 数据”，而是在改写 UMI 的模态边界。

上游数据 / 项目页 / 相关文章：exUMI

7. Touch in the Wild / ManiWAV / MV-UMI

这三条我会放进“强相关 UMI-like”组一起看。`Touch in the Wild` 用 portable visuo-tactile gripper 走向精细接触操作；`ManiWAV` 把 contact audio 并进 handheld 数据接口；`MV-UMI` 则给 wrist-only UMI 加上第三人称视角，减少长时任务中的上下文缺失。它们共同说明：UMI 现在已经不只是一个系统名，而在逐渐变成一整套可扩展的数据接口家族。

Touch in the Wild / ManiWAV / MV-UMI

如果你只想记一个判断： `UMI` 公开数据现在已经可以分层理解了。最核心的还是 Stanford 原版官方上游数据；最适合做规模化整理的是 `FastUMI` 系列；而最能代表“下一代手持无本体接口在往哪里长”的，是 `exUMI`、`Touch in the Wild`、`ManiWAV` 和 `MV-UMI` 这些新模态和新视角扩展。
但不要把“上游数据”和“镜像版”混成一回事： `lerobot/umi_cup_in_the_wild`、`DaivdYuan/exumi-*-lerobot` 这类条目非常适合直接进入训练工具链，但它们本质上是转换版。真正做数据调研时，更应该把 Stanford 官方 `Zarr`、FastUMI 官方数据页和 exUMI 上游 `zarr.zip` 仓库当成主入口。

先给一个总判断

我现在越来越不把“数据采集”理解成论文里的配套工程，而更把它看成具身智能里的基础设施设计。因为模型最终能学到什么，常常不由结构名字决定，而是由你能不能稳定采到 时间对齐、动作可执行、场景多样、接口一致 的数据决定。

一句话记忆： 最近这些数采方案，本质上都在回答同一个问题：如何把人类操作、机器人控制和真实世界场景，压成一份模型真正学得动的数据。

最近主流数采方案，其实分成三条路线

路线一：机器人本体 teleoperation

代表是 `ALOHA`、`ALOHA 2`、`Mobile ALOHA`。这一路线的优势是动作和机器人本体天然对齐，缺点是采集带宽、成本和场景灵活性容易受机器人硬件本身限制。

路线二：分布式机器人数据管线

代表是 `DROID` 和 `BridgeData V2`。它们的重点不是新型人机接口，而是用更标准化的硬件和更广的环境覆盖，把大量真实机器人演示组织成一个可训练的数据集。

路线三：人类中心、硬件解耦的数据接口

代表是 `UMI`、`DexUMI`，以及更近的 `Being-H0.5` 里的 `UniCraftor`。这条路线最有野心，因为它不满足于“直接 teleop 机器人”，而是想把人类自身的操作痕迹转写成跨机器人可迁移的数据语言。

第一条路线：机器人本体 teleoperation 仍然非常重要

ALOHA / ALOHA 2

`ALOHA` 的贡献不只是便宜，而是它证明了：低成本双臂 teleoperation 也可以支持精细、接触丰富、闭环视觉依赖很强的任务。`ALOHA 2` 则继续把这个方向工程化，增强 gripper、重力补偿、机架和相机系统，目的都是让数据采集更稳、更耐用、更适合规模化复用。

为什么这条线还重要： 因为它采到的是最“机器人原生”的数据。动作直接发生在目标本体上，控制接口天然成立，所以非常适合做高精度、强接触、双臂协同类技能。

Mobile ALOHA

`Mobile ALOHA` 进一步说明，具身数据采集不能只停留在桌面抓取。它把 whole-body teleoperation 带进移动双臂任务，覆盖开柜门、进电梯、厨房长时操作这类更像真实服务机器人的场景。它最值得记住的一点，是论文明确展示了 co-training with static ALOHA data 可以把移动任务成功率显著拉高。

这一条路线的研究意义： 它在证明“机器人本体 teleop 仍然是高质量技能数据的金标准之一”，只是这条路很难单独解决规模和场景多样性的问题。

第二条路线：把真实机器人数据做成可扩展的数据集

DROID

`DROID` 代表的是另一种思路：不一定改变交互接口，而是把机器人平台、采集协议、场景覆盖和数据组织方式标准化。它的亮点不是一个新奇的控制器，而是 76k 条轨迹、564 个场景、86 个任务、13 个机构的分布式采集组织能力。

这类方案告诉我们，数据质量不只来自“单条示范很精致”，还来自“整体分布是不是够广、够真实、够多样”。

BridgeData V2

`BridgeData V2` 则更像一个特别好的研究型基座。它用 VR teleop 在 24 个环境里采了 60,096 条轨迹，覆盖 13 个技能，并且保留语言标注、多视角相机和 wrist camera。它很适合帮助建立一个最朴素但很重要的直觉：当任务和环境真正扩展时，策略泛化会随数据组织质量一起提升。

这一路线的局限： 它很强，但采集还是绑定在机器人本体上，所以在带宽、成本、维护和部署场景灵活性上，天然会比人类中心接口更重。

第三条路线：为什么 UMI 依然是最值得深挖的核心节点

如果只让我挑一个数采方案深入读，我还是会首推 UMI。原因很简单：它不是在优化某个 teleop 细节，而是在重新定义“什么样的人类示范才能转写成机器人可学数据”。

它把数据采集和部署接口绑在一起

UMI 最深的地方，是从一开始就考虑 latency matching、relative trajectory 和 deployment consistency，而不是先采再说。

它显著提高了数据采集带宽

项目页展示它的示范速度大约 111 次/小时，远快于传统 SpaceMouse teleop 的 35 次/小时，说明它不只是接口更对，也确实更快。

它天然更适合跨机器人迁移

因为它不是把动作死死绑在某一台机器人上，而是在尽量学习一种更接近操作语义本身的局部动作接口。

我的理解： ALOHA 很强，DROID 很强，但 UMI 更像是在问一个更靠前的问题：我们到底应该如何定义一条具身示范，才能让它成为基础模型时代真正可复用的训练样本。

和 UMI 最像的新方向：Being-H0.5 里的 UniCraftor，以及最新的 U1 Real DexUMI

这条线对应的是北京创业公司 BeingBeyond（智在无界）。他们 2025 年先做了 Being-H0 —— 首个大规模人类视频预训练的灵巧手 VLA；2026 年发布 Being-H0.5：`Scaling Human-Centric Robot Learning for Cross-Embodiment Generalization`（PDF / arXiv 2601.12993 / Code）。这篇工作里最值得放进数采专栏的，不只是模型，而是它提出的 UniCraftor 数据采集系统以及配套的 UniHand-2.0 数据集（35,000+ 小时）。

和 UMI 的共同点

两者都在走“人类中心、硬件解耦”的路线，都不满足于只做机器人本体 teleop，而是试图把人类交互痕迹转写成跨 embodiment 可迁移的训练信号。

它比 UMI 更强调什么

`UniCraftor` 特别强调 native RGB-D、稳定校准带来的 world-frame consistency，以及 contact / release 这类关键事件触发。它想进一步把"高质量数据"定义成几何、时间和交互事件都可被精准恢复。

为什么值得持续观察

如果 UMI 解决的是可部署接口，那么 UniCraftor 想走得更远：它想把跨 embodiment 预训练所需的统一动作语言和同步数据采集一并做掉。这条线很可能会对下一代 generalist policy 产生更大影响。

2026-03：U1 —— 全球首款 Real DexUMI

BeingBeyond 在 2026 年 3 月正式发布 U1，被官方称为"全球首款 Real DexUMI"（雷峰网深度报道 / 新浪科技 / 官方 X 公告）。它真正的意义在于：把 UMI 范式的核心主张——无本体 / 低成本 / 真实场景可规模化——首次落到了"灵巧手"而不是"平行夹爪"。

硬件参数

整机 680g，11 关节（6 主动 + 5 被动），承重 5kg，指腹集成触觉传感器，动态追踪最大误差 <1mm、平均误差 <0.1mm。

同构掌心遥操手套

它最大的工程创新是"同构掌心遥操"—— 不需要复杂穿戴或校准，手套置于手心即可操作。这把采集门槛降到了几乎和手持 gripper 一样低，但获得的是完整的多指灵巧操作数据。

"末端本体一致性"设计原则

U1 的"Real"指的是：采集端、遥操端、部署端用的是同一套灵巧手末端本体，从而在几何、运动学、视觉外观上都天然对齐，直接解决了 Stanford DexUMI 需要 inpainting 的视觉差距问题。

它和 Stanford DexUMI 的本质区别： Stanford DexUMI 是"人手戴 exoskeleton 模拟灵巧手 + video inpainting 抹掉人手"； BeingBeyond U1 是"真 · 一套末端 → 采集与部署共用本体"。前者是学术方案，后者更像工业化产品——这也是它敢自称 Real DexUMI 的原因。
但要保持审慎： U1 和 UniHand-2.0 的很多实测指标目前主要来自官方公告和产业媒体，公开复现、基准对比、独立评测都还在进行中。如果你关注这条线，建议同时跟踪 BeingBeyond 的 research 站点 和 GitHub 组织，看他们后续会放出什么级别的开源。

DexUMI：UMI 往灵巧手方向长出的第一条重要分支

`DexUMI` 很值得深挖，因为它说明 UMI 的思想并不只适用于平行夹爪 manipulation。一旦你把目标从平行夹爪扩展到多指灵巧手，问题会突然变难很多：人手和机器人手在自由度、几何结构、接触方式和视觉外观上都不再接近。

硬件上：用 exoskeleton 缩小运动学差距

DexUMI 不再只是让人拿着“像 gripper 的工具”，而是直接让人戴上面向目标机器人手设计的可穿戴 exoskeleton。这样示范时就能保留人手的直接触觉反馈，同时把动作约束到更接近目标灵巧手可实现的轨迹空间里。

视觉上：用 robot-hand inpainting 缩小外观差距

DexUMI 很聪明的一点，是承认“人手长得和机器人手就是不一样”。于是它在训练数据里把人手和 exoskeleton 替换成高保真 robot-hand inpainting，让策略在视觉上看到的东西更接近部署时真实机器人会看到的东西。

表示上：relative trajectory 继续成立

和 UMI 一样，DexUMI 依然受益于 relative action 表示。项目页里甚至专门展示了 finger action 采用相对轨迹比绝对轨迹更稳定，这说明 UMI 的接口思想在灵巧手上并没有失效，反而更重要。

我对 DexUMI 的判断： 它不是简单的“灵巧手版 UMI”，而是在回答 UMI 原始设想能否跨过最难的一道坎：当人类操作者和目标机器人在手部结构上严重不一致时，数据接口还能不能成立。

Mobile UMI 不是一篇论文，而是一整个方向

如果说 DexUMI 是把 UMI 从平行夹爪推向灵巧手，那么另一条更大的外延，就是把 UMI 从固定底座 manipulation 推向 mobile manipulation 与 whole-body manipulation。这一方向我更愿意叫它 `mobile UMI family`，因为它其实包含了多篇互补的工作。

UMI-on-Legs

这篇的核心不是重新定义数据接口，而是证明 UMI 采到的 manipulation policy 可以通过 manipulation-centric whole-body controller 被“插”到四足移动平台上。它很重要，因为它首次让 UMI 风格数据和 whole-body controller 形成 plug-and-play 接口。

HoMMI

`HoMMI` 更进一步。它意识到移动操作不只是手怎么动，还包括人要怎么找路、怎么看、怎么协调头部和双手。所以它给 UMI 增加了 egocentric sensing，专门去捕捉 mobile manipulation 所需的 global context、active perception 和 hand-eye coordination。

HuMI

`HuMI` 则把 robot-free demonstration 进一步推进到 humanoid 的 whole-body manipulation：包括 walking、kneeling、squatting、tossing 和双臂任务。它最重要的意义在于说明 portable robot-free collection 不再只服务机械臂，而是开始服务 whole-body humanoid skill acquisition。

为什么 mobile UMI 方向比看上去更难

观测差距更大

固定底座操作主要靠 wrist view 和局部任务状态，但 mobile manipulation 需要全局上下文、导航线索、主动观察和多身体部位协同。HoMMI 会强调 head-mounted egocentric sensing，正是因为 wrist-only 根本不够。

动作差距更大

人类在示范时不只是移动夹爪，还会转头、挪步、下蹲、前倾、改变重心。到了移动平台、四足、humanoid 上，这些动作该怎么映射，已经远不是原始 UMI 那种相对末端轨迹接口就能完全覆盖的。

控制器必须补上更多“下半身智能”

`UMI-on-Legs` 和 `HuMI` 都说明，数据接口只是上半场。真正落地 whole-body/mobile 系统时，还必须有强 whole-body controller 把高层手眼轨迹转成稳定、可执行的全身动作。

这也是为什么我不把 mobile UMI 看成“UMI 的自然小改版”： 它其实是在把 UMI 的核心命题从“人类示范如何转成机器人操作数据”升级成“人类 whole-body 行为如何转成不同机器人身体上的可执行技能”。

UMI 最近的动态：这条线正在往三个方向长

1. 从单模态到多模态

`TacUMI` 这类 2026 新工作已经开始把 tactile、force-torque 和 pose tracker 接入 UMI 风格接口，重点针对 cable mounting 这类 contact-rich 任务。这说明大家开始意识到，仅有视觉和位姿并不足以覆盖更复杂的接触操作。

2. 从平行夹爪到 dexterous / mobile / whole-body

`DexUMI`、`UMI-on-Legs`、`HoMMI`、`HuMI` 说明 UMI 不再是一个单点系统，而是在长成一个家族。这个家族正在分别解决灵巧手、移动操作、active perception 和 humanoid whole-body 的新 embodiment gap。2026-03 BeingBeyond U1 又加了一个重要节点——它是目前第一个公开以"Real DexUMI"自命名的商业化灵巧手采集本体，主张采集端和部署端共用同一套末端。详见 本页的 Being-H0.5 / U1 章节。

3. 从论文系统到数据生产线

`FastUMI-100K` 和 `FastUMI Pro` 代表的是规模化方向。前者开始把 UMI 风格数据做成更大规模的数据集，后者则更像工业化数采背包，把 UMI 从实验室方法推进到标准化数据生产设备。

4. 从单一接口到更大的跨 embodiment 语言

不管是 UMI 的后续扩展，还是 Being-H0.5 里的 unified action language，都在说明同一件事：未来真正重要的，不只是“采到更多数据”，而是“采到能进入统一动作语言的数据”。

我对这条线的判断： UMI 已经不只是 RSS 2024 的一篇系统论文，它越来越像一个数据接口家族的起点。
但数据开源节奏并不一致： `MV-UMI`、`exUMI`、`Touch in the Wild` 这类更贴近 handheld 接口扩展的工作，已经开始有公开数据；但 `DexUMI`、`UMI-on-Legs`、`HoMMI`、`HuMI`、`UMI-FT` 这些更偏灵巧手、移动平台和 whole-body 的分支，目前我主要能确认有公开论文、项目页或代码，而没有找到像 `UMI cup_in_the_wild`、`FastUMI-Data` 或 `exUMI` 那样稳定清晰的公共数据下载入口。所以如果你的目标是“今天就下载来用”，最现实的入口仍然是上面列出来的这些 handheld / UMI-like 数据。

如果按研究价值排序，我会怎么读这些方案

  1. 先读 UMI，因为它最能建立“数据接口”这层直觉。
  2. 再看 `DROID` 和 `BridgeData V2`，理解真实机器人数据怎样被做成规模化数据集。
  3. 接着看 `ALOHA / Mobile ALOHA`，理解机器人本体 teleop 为什么仍然是高质量技能数据的重要来源。
  4. 然后重点看 `DexUMI` 和 `UMI-on-Legs / HoMMI / HuMI`，因为它们最能告诉你 UMI 这套接口思想能否跨过 dexterous 和 mobile/whole-body 这两道最大的坎。
  5. 最后持续跟踪 `Being-H0.5 / UniCraftor`、`TacUMI`、`FastUMI` 这类更近的新方向，看这条线会不会真的把数据采集推进到 foundation-model 级基础设施。

如果只记住四句话

  1. 具身智能的数据采集，不再只是“录示范”，而是在设计训练接口。
  2. ALOHA、DROID、BridgeData V2 解决的是高质量机器人原生数据怎么来；UMI、DexUMI、HoMMI、HuMI、UniCraftor 解决的是人类示范怎么转成跨机器人可复用数据。
  3. UMI 仍然是这条线里最关键的节点，因为它最早把数据质量、时间对齐和部署一致性绑在一起讨论。
  4. DexUMI 和 mobile UMI family 最值得深挖，因为它们直接测试了 UMI 思想能不能跨过灵巧手和 whole-body/mobile 这两类 hardest embodiment gaps。
  5. 最近的新变化很明确：更多模态、更大规模、更统一动作语言，会成为下一代数采系统的主方向。
