先抓住三条主线

VLA 论文很多，但你可以先记住这三条线，后面的文章基本都是沿着它们展开。

主线一：把语义接到动作上

`RT-2`、`OpenVLA` 解决的是“怎么让模型看懂图像、听懂语言、再输出动作”这个最初级但最关键的问题。

主线二：让模型在真实时间里来得及反应

`UMI`、`Psi0`、`Xiaomi-Robotics-0`、`VLASH`、`FASTER`、`Fast-WAM` 关心的是部署延时、动作衔接、状态错位和推理负担。

主线三：从机械臂走向 humanoid whole-body

`Psi0`、`Heracles`、`SMASH` 说明问题已经不只是抓取，而是语义理解、全身控制、恢复能力和低层执行要一起工作。

为什么我单独开了“低延时专题”

因为现在 VLA 的真实瓶颈，已经不只是能不能输出动作，而是能不能在合适的时间输出对的动作。

UMI：先把时间轴对齐

UMI 看到的问题是：训练时的人类示范几乎没有系统延时，但机器人部署时有相机延时、推理延时、执行延时。如果不补偿，动作天然错拍。

VLASH：让模型面向未来状态预测

VLASH 看到的问题是：异步推理时，模型开始想的时候和动作真正上身的时候，中间隔着一段时间，所以要把机器人状态往前滚。

FASTER：先把最急的动作做出来

FASTER 看到的问题是：近端动作和远端动作不该被同等对待。最靠近当前时刻的动作最重要，应该最先完成。

进入低延时专题

我对这波论文的判断

如果把 2025-2026 的工作压缩成几句话，我最想让刚入门的人记住下面四点。

1. 实时性已经变成一等公民问题

低延时不再是部署工程师单独处理的“边角问题”，而是论文主贡献本身。

2. 强语义能力和强动作能力并不会自动兼容

很多论文都在处理同一个矛盾：机器人数据让模型更会动，但也可能让原本的视觉语言理解退化。

3. Humanoid 几乎必然走向分层系统

whole-body 控制涉及稳定性、动力学和接触约束，完全端到端在短期内很难成为主流。

4. 数据闭环与控制闭环越来越重要

越往后看，大家越在意 sim-real、恢复能力、时间对齐和真实世界数据，而不只是模型参数量。

如果把研究重心放回第一性问题

越往后读我越觉得，VLA 论文不能只盯着“实时推理”“模型结构”“参数规模”这些最显眼的层。更本质的问题是：什么样的数据和接口，才能真正训出一个更强、更稳、更可迁移的具身基础模型。

1. 实时推理是重要约束，但未必是当前最该优先猛攻的研究中心

实时性当然重要，因为机器人必须在正确时间输出正确动作。但在很多阶段，它更像是一个必须理解的系统边界条件：你要知道 latency 从哪里来、为什么会损伤控制闭环、异步推理为什么会造成状态错位，而不一定一开始就把主要精力放在极限加速上。

2. 和硬件最有研究含金量的结合点，往往是接口设计而不只是算力加速

如果说实时推理主要讨论“系统是否来得及反应”，那么 `UMI` 更像是在讨论“人类示范、观测、动作、设备和机器人部署”怎样被连成同一个可学习闭环。它真正有价值的地方，不只是低延时，而是让数据接口和执行接口彼此对得上。

3. 更值得长期投入的主线，是如何训出一个更好的基础模型

真正决定上限的，往往不是把 inference 再压快 20ms，而是基础模型是否已经学到稳定、可组合、可迁移的 embodied prior。只要这个 prior 还不够强，后面的部署优化很多时候就只是修边角。

4. 训练表现常常只是数据质量的外显结果

模型最后体现出的泛化、稳定性和恢复能力，本质上经常是在反映数据有没有覆盖关键状态、有没有正确时间对齐、有没有足够高质量的示范、有没有把失败和长尾边界也纳入分布。换句话说，训练不是不重要，而是它经常在放大数据本身已经包含的结构。

这会把我看论文的角度改成什么

如果接受上面的判断，那么之后再读具身论文，我最想追问的就不再只是“模型结构有没有更新”，而是下面这些更本质的问题。

这篇工作到底带来了什么新数据

是新任务、新视角、新传感器，还是新的人机交互方式？如果没有新的数据来源和数据质量提升，很多结构改进的上限其实很快就会暴露。

它有没有改善“数据和动作”的对齐关系

具身不是只看图像语义，而是要看 observation、language、action、time 这四件事是不是被对齐了。`UMI` 值得重视，恰恰是因为它在这个问题上很本质。

它是否让模型学到更可迁移的 embodied prior

真正好的基础模型，不该只会某几个 benchmark 上的技能，而应该在新场景、新物体、新扰动下还能延续已有能力。这个能力更多取决于数据覆盖和任务组织方式，而不只是参数量。

我现在更认同的一句话

对于具身智能，论文观察的核心方向，也许可以被压缩成一句很朴素的话：如何得到更好的数据。

“更好的数据”不只是更多数据

它包括更好的时间同步、更少的示范噪声、更覆盖长尾失败的样本、更贴近真实部署分布的任务设计，也包括更合理的数据筛选、重标注和组织方式。

“更好的数据”决定了什么问题值得做算法

算法当然重要，但它更像是放大器。只有当数据里本来就含有值得学的结构时，算法创新才会真正产生持续收益。否则很多方法改进只是对已有数据分布的过拟合式包装。

“更好的数据”也会重新定义博客后续重点

所以接下来如果我继续写这个 blog，我会更系统地追踪三类内容：高质量 teleoperation/示范数据怎么采、跨机器人和跨任务数据怎么统一、以及 foundation model 怎样从这些数据里学到真正稳定的动作先验。

沿着这条线，最值得继续看的高质量论文

如果把视角从“模型又换了什么结构”改成“怎样得到更好的具身数据、怎样训练更好的基础模型”，下面这些工作会比单纯追逐部署加速更值得反复看。

Interface / Data Collection

UMI

重点不是“采得快”，而是把人类示范变成机器人真的能学、真的能部署的数据接口。

In-the-Wild Dataset

DROID

最值得看的点是它如何把多机构、564 个场景、86 个任务的数据组织成真正能提升鲁棒性的高质量训练资源。

Cross-Embodiment Dataset

Open X-Embodiment

如果你想理解“基础模型为什么需要跨机器人数据”，这几乎是绕不过去的起点。

Scaling Dataset

BridgeData V2

它很适合帮助建立一个直觉：当任务和环境多样性真正增加时，策略泛化是如何随数据规模一起上升的。

Generalist Policy

Octo

它的重要性不只在模型本身，更在于它展示了怎样把异构数据混合、筛选和标准化成可预训练的 mixture。

Teleoperation System

Mobile ALOHA

它提醒我，teleoperation 系统的设计本身就会决定你最终能采到什么样的 whole-body 数据。
